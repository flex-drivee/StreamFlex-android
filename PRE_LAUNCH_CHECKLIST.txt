## 📦 Repository Structure Recommendation

### Should you move providers/extractors to `streamflex-providers`?

> **For Sep 15 Launch → NO. Keep everything in the main repo.**

**Why NOT now:**
- Only 3 days left — splitting repos requires a full plugin loader system (APK/DEX loading, version compatibility checks, plugin signing). That's 2+ weeks of work minimum.
- The `streamflex-providers` repo currently only contains **JSON manifests** (domain configs), not Kotlin code.
- A broken plugin loader on launch day would be a disaster.

> **After launch → YES, plan it for v2.0**

**What v2.0 structure looks like:**
```
streamflex-android/         ← main app (engine, UI, player)
streamflex-providers/
  manifests/                ← JSON configs (already here, already working!)
  plugins/                  ← future: compiled .apk plugins
    hdhub4u.apk
    animedekho.apk
    moviebox.apk
```
**Benefits post-launch:**
- New providers without app update
- Community can contribute providers
- Domains already hot-swappable via JSON (already works!)
